# 调用链与死代码否证：为什么这不是一段没人调用的代码

> 主报告 A1/A2 的**活性证明**。
>
> **为什么需要这一篇**：静态分析里最容易被质疑的一句话是——
> 「你在二进制/资源里找到一段代码，怎么证明它**真的会被执行**？」
> 死代码（dead code）、废弃分支、只在开发环境走到的路径，都是真实存在的。
> 如果这条链断了，A1/A2 的定性就要撤回或降级。
>
> 本文件逐环给出证据，**每一环都可用 `grep` 复核**。

---

## 0. 结论先说

**不是死代码。** 从 App 入口到网络出口，**七环全部闭合**，且其中
**第 2↔3 环是模块级绑定**（webpack 模块 id），不是「定义存在」这种弱证据。

此外，**同一条链的每个环节都独立于我们的分析**：第三方用 `grep` 与文本编辑器
即可逐环复现，不需要反汇编器，不需要信任我们。

---

## 1. 七环调用链（逐环证据）

### 环 1 · 入口

`www/index.html`：

```html
<script src="cordova.js">
<script src="./js/index.js">
<script src="./umi.js">          ← 主 bundle
```

`umi.js` 是主 bundle，所有业务 chunk 由它按需加载。

**复核**：
```bash
grep -o '<script[^>]*src="[^"]*"[^>]*>' www/index.html
```

---

### 环 2 · 路由注册

`www/umi.js` @978087 的路由表中：

```js
{
  path: "/login",
  component: Object(f["c"])({
    loader: () => Promise.all([n.e(4), n.e(10), n.e(109), n.e(58)])
                    .then(n.bind(null, "zuap"))
  }),
  exact: !0
}
```

**关键**：`n.bind(null, "zuap")` —— 加载完成后**绑定到模块 id `zuap`**。
这是模块级绑定，不是字符串提及。

**复核**：
```bash
grep -o 'path:"/login",component:[^}]*}[^}]*}' www/umi.js
```

### 环 3 · chunk 表与模块 id

`www/umi.js` @2654 的 chunk 名称表：

```js
{ …, 57:"p__joinapp", 58:"p__login__Login", 59:"p__login__MobileVaild", … }
```

⇒ chunk **58** = `p__login__Login`，与环 2 的 `n.e(58)` 对应。

而 `www/p__login__Login.js` 文件头：

```js
(window["webpackJsonp"]=window["webpackJsonp"]||[]).push([[58],{
  Qddd: function(e,r,o){…},        // 样式模块
  "RG+Z": function(e,r,o){},       // 空模块
  dQEH: function(e,r,o){…},        // 样式模块
  zuap: function(e,r,o){ … }       // ← 环 2 绑定的就是它
}]);
```

**⇒ 环 2 的 `"zuap"` 与环 3 的模块 id `zuap` 是同一个东西。链条在这里是硬的。**

**复核**：
```bash
grep -o '58:"p__login__Login"' www/umi.js
grep -o 'zuap:function' www/p__login__Login.js
```

`www/p__login__Login.js` @9617：

```js

    if (r) console.log("Validation failed");
    else {
```

而 `Q` 定义在同文件 @9453：

`X` 里 `g({type:"login/tryLogin", …})` 是一次 dva dispatch。

```js

    … i(s, r) …            // s = service 函数，r = e.payload
```

service `s` 定义在 `umi.js` @420661：

## 3. 为什么这构成「非死代码」的证明

死代码的判定条件有三条，本链**三条全部不满足**：

| 死代码判定条件 | 本链实测 |
|---|---|
| **无绑定**（定义了但没挂到任何事件/回调） | ❌ 两个按钮的 `onClick:X`（@12186 / @13761） |
| **无路由触达**（页面本身进不去） | ❌ `/login` 路由注册在 umi.js 路由表，loader 绑定 `zuap` |
| **无调用方**（函数没人调） | ❌ `X` 由 onClick 调；`Q` 由 `X` 调；`tryLogin` 由 `X` 的 dispatch 调；service `s` 由 effect 调 |

**再加上一条更强的**：环 2↔3 是**模块级绑定**（`n.bind(null,"zuap")` ↔ 模块 id `zuap`），
不是「某处提到过这个字符串」。这意味着**只要路由能进，这个模块就必然被实例化**。

## 4. 第二条链（框架层，独立于组件层）

即使组件层的链被质疑（比如「也许那个按钮是隐藏的」），还有**第二条独立链**：

`www/umi.js` 的 `login` model 中，`resetPossword` effect @425339：

```js
c && (o.phone        = S(c));      // 手机号
l && (o.validateCode = S(l));      // 验证码
d && (o.password     = S(d));      // 密码
o = {...o, encryption:"1"};        // 显式加密模式标记
s(y, o);                           // → POST /api/user/password
```

其中 `S` 定义在 `umi.js` @423347，**用同一把密钥**：

```js
S = e => {
  var t = "385f33cb…9081ab7";
  t = T.a.enc.Utf8.parse(t);
  var n = T.a.AES.encrypt(e, t, {mode: T.a.mode.ECB, padding: T.a.pad.Pkcs7});
  return n.ciphertext.toString()
}
```

**这条链的意义**：它不依赖登录页的 UI——它是 **dva model 的 effect**，
由「重置密码」页面的 dispatch 触发。**两条链互不依赖，任一条成立即证明钥是活的。**

## 5. 一处必须如实说明的边界

**静态证明的是「点登录按钮即执行」。**

它**不能**证明：
- 用户实际会点（但这由产品语义保证——登录是登录页的主按钮）；
- 运行期没有额外的拦截/短路（静态看不到运行时分支）。

若要运行期实证（抓包看 ECB 密文形态），属**动态窗口**工作，本报告未做。
**但 A1/A2 的定性不需要它**——死代码的判定条件已全部不满足。
